# orbistoun-shader

Guest shader bytecode: decode it, and measure how much of it is understood.

It holds the instruction encoding tables (`data/*.toml`, generated by
[orbistoun-gen](../orbistoun-gen/)), the decoder, and the census that ranks what is missing.
An opcode it cannot solve is reported as unsolved, never decoded to something plausible.
[orbistoun-translate](../orbistoun-translate/) consumes the decoded instructions, and
`orbistoun-cli shaders` prints the census.

## The census

Writing a shader compiler is not a search problem, but deciding what to build next is a
counting problem. For a corpus of shaders the census answers: how many distinct instructions
are in use, which are not understood, and which single one, if supported, would unblock the
most shaders. That turns an unbounded compiler project into a ranked worklist, the same move
the import survey makes one layer up. It needs no GPU, no driver and no running emulator.

## Rule

A test that iterates over what the code produced and validates each item passes when the code
produces nothing. So every decoder output that is empty by design - an instruction with no
operands, for instance - is listed in an exact inventory with its reason, and anything empty
outside the inventory fails (see [docs/TESTING.md](../../docs/TESTING.md)).
