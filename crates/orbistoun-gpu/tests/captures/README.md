# Command-stream captures

Recorded from a running guest, and the only material in this crate that was not
generated by it.

## Why these exist

`../../data/packets.toml` says which packet opcodes write hardware registers, what their
base offsets are, and which registers hold a shader address. Every one of those is
transcribed from published documentation and **checked against nothing**. Its own comment
calls the shader-address rows the least certain thing in the file.

Everything downstream of that table is verified: instruction decoding against a reference
disassembler, translation against a real GPU. The table itself is the one place where a
mistake would be silent - a wrong base attributes every register write in its class to
the wrong register, consistently, and a wrong shader-address row means shaders are looked
for in the wrong place. Neither produces an error. Both produce a submission that yields
nothing and looks like an unremarkable frame.

A capture is what breaks that circle.

## What a capture is, and why it is a *pair*

The guest's graphics layer is a command-buffer builder: library calls append packets to a
buffer the guest owns, and a separate call submits it. So a capture records **both sides
of one call**:

- what the guest asked for, as arguments the shim observed
- the bytes that call appended

A raw command buffer on its own is not enough. It would still have to be read *through*
the table under test, so agreement would prove nothing. The pair is self-checking: the
call states the answer, the bytes are the question.

## Format

Two files per capture, sharing a stem:

    <name>.toml   what the call said
    <name>.bin    the bytes it appended

```toml
# Which library call this came from, and which queue the buffer belongs to.
call  = "sceAgcCreateShader"
queue = "compute"                  # "draw" or "compute"

# Optional free text: anything about the capture worth knowing later.
note = "first draw of the title's boot logo"

# A register the call is known to have written. The most direct expectation there is:
# it depends on nothing but the packet walk and the register bases.
[[register]]
register = 0x2E0C
value    = 0x0001_0000

# A shader the call is known to have set up. Depends additionally on the
# shader-address rows and on the halves being paired the right way round.
[[shader]]
stage   = "compute"
address = 0x0000_0001_0000_0000
```

Both lists are optional and a capture may contain either or both. An expectation that is
not known should be **left out**, never guessed - a fixture asserting something the
capturer inferred rather than observed would turn this from an oracle back into a mirror.

## Adding one

Drop the pair in this directory. `tests/vocabulary.rs` picks it up with no registration
step, and will say so if the two disagree.

If the corpus is empty the test reports that loudly rather than passing quietly, because
"nothing to check" and "everything checks out" must never look the same.

## Provenance

These are **observations of behaviour**, which cross the boundary freely: bytes a guest
produced, and arguments it passed. Nothing here may be derived from reading another
implementation's source. See [PROVENANCE.md](../../../../docs/PROVENANCE.md).
