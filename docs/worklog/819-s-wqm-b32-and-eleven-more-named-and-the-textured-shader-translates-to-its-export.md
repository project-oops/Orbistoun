# 819. `s_wqm_b32` and eleven more of the textured pixel shader's opcodes are named by the reference, whole-quad mode translates for 32 lanes, and Neverball's fragment shader now translates to its last seven words

**2026-09-24** — worklog 818 found every one of Neverball's 450 draws refused for want of a fragment
shader, which stopped translating at byte `0x84` on an opcode with no recorded name.

## What the instruction is

The fragment shader is the GL context's textured pixel shader, a variant copy in the payload's ring at
`0x6000` (oops-sdk `gl_internal.h`, `OOPS_GL_PS_RING_OFFSET`). Byte `0x84` is word 33, which
`gl_ps_build_textured` writes as `0xbefe097e` — **`s_wqm_b32 exec_lo, exec_lo`**, whole-quad mode, so
the helper pixels of each covered quad run the texture sample and its level-of-detail derivatives exist
(oops-sdk `tools/shader/tex-prolog.s`). The cube's untextured shader never samples and never reached it.

## Naming: a fixture, not a hand edit

`mnemonics.toml` is generated by `orbistoun-gen fixtures` from instructions a reference toolchain
assembled and named (D681): every entry observed, none guessed. The table had `s_wqm_b64` (a compiled
wave64 sampling fixture emits it) and not the 32-lane form. Diffing every mnemonic in the SDK's
textured-path assembly (`tex-prolog.s`, `tex-env.s`, `fog.s`, `alpha-test.s`, `polygon-stipple.s`,
`coverage-tex.s`, …) against the table, suffixes normalised, found twelve missing: `s_wqm_b32`,
`s_and_b32`, `s_branch`, `v_and_b32`, `v_cvt_u32_f32`, `v_sub_f32`, and six compares
(`v_cmp_eq/ge/gt/le/neq_f32`, `v_cmp_ne_u32`). Several the translator already implements but could not
reach, because the decoder had no name to dispatch on.

**`tools/shader-fixtures/texture.s`** assembles all twelve in the SDK's own forms, like `primitive.s`
did for the cube's vertex program (worklog 545). Two details: the compares are spelled with `vcc` —
the generator's target is wave64 and a VOPC carries no destination field, so the word is the same —
and the branch is a word count, not a label, because the reference prints a label by name and the
differential test then (rightly) could not compare it with the decoded offset. Generated in the
toolchain VM (`orbistoun-build`); the VM's tree is a pushed copy, not a mount, so only
`mnemonics.toml` and the `texture.gcn`/`.txt` pair were pulled back, and the table's diff is **purely
additive: the twelve entries and nothing else**. `differential.rs` lists the new fixture.

## Translating it

`s_wqm_b32` joins the supported list and the mask-model set beside `s_wqm_b64`, and
`whole_quad_mode_32` translates it: read the one source register, fold each four-bit group with the
existing `quad_expand`, and write the result where `s_mov_b32` would — `exec_lo`/`vcc_lo` through the
mask's low half, or a scalar register. `whole_quad_mode_32_lights_the_quad_of_every_set_bit_and_nothing_else`
runs it on the device: bit 0 lights `0b1111`, bit 4 lights `0b1111_0000` and not the first quad, and an
empty mask stays empty.

## What Neverball's shader does now

```
did not translate: fragment at 0x740001656000: ... instruction at 0x488 cannot be translated:
  this target has no recorded name for that opcode
```

From byte `0x84` to byte **`0x488` of `0x500`** — the sampling prologue, the combine, fog, the alpha
test and the coverage slots all translate. Word 290 is the export slot (`GL_PS_EXPORT_TEX`), and it
opens with **`v_cvt_pkrtz_f16_f32`**, the pack of four colour floats into two half-float registers that
the compressed export behind it (`exp mrt0, v4, v5 done compr vm`) sends — the SDK moved to the
half-float export on 2026-09-23 for 8_8_8_8 targets. Naming and translating that pack, and the
compressed export, is the next unit; the 450 draws stay refused until the fragment module exists.
